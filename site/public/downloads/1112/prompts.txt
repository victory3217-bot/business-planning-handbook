프롬프트 모음 — 사업계획서 디벨롭 (콘텐츠 비즈니스)

사용법: [대괄호]는 내 정보로 바꾸고, 아래 「공통 조건 5줄」을 모든 프롬프트 맨 아래에 그대로 붙여서 AI에 넣습니다.
고객 이름·연락처·계정명 같은 개인 정보는 넣지 않습니다. AI가 말한 숫자는 내가 다시 계산합니다.

==================================================
공통 조건 5줄 (모든 프롬프트 맨 아래에 붙이기)
==================================================
① 내가 붙여 넣은 자료에 없는 숫자·사실은 만들지 말고 「[확인 필요]」로 표시한다.
② 모든 문장 끝에 이름표를 붙인다: [입력자료] / [계산] / [추론] / [확인 필요].
③ 계산은 계산식을 보여 준다.
④ 가정한 내용은 마지막에 「가정 목록」으로 따로 모은다.
⑤ 업계 평균·벤치마크 숫자는 출처와 연도를 제시할 수 없으면 쓰지 않는다.

프롬프트 ① BM 약한 고리 진단 (공통)
==================================================
[역할]
너는 콘텐츠 사업을 보는 사업기획 컨설턴트다.

[입력 자료]
아래는 내가 작성기 CH05에서 쓴 답변이다.
[여기에 CH05 .md 내용을 붙여 넣는다]
내 목표 한 줄: [예: 12개월 안에 월 매출 1,000만 원]

[과업]
1. 내 BM을 「고객 → 문제 → 가치 → 채널·관계 →
   자원·활동·파트너 → 비용·수익」 한 문장으로 다시 써라.
2. 문장이 끊기거나 서로 모순되는 곳을 최대 3개 찾아라.
3. 끊기는 곳마다 「어느 칸인지 / 왜 끊기는지 /
   지금 확인할 가정 한 문장」을 써라.
4. 내가 쓰지 않아 네가 추측한 칸은 따로 표시해라.

[제약]
- 입력에 없는 숫자와 사실은 만들지 않는다.
- 원가와 가격은 방향만 말하고 숫자를 넣지 않는다.

[출력 형식]
표: 번호 | 칸 | 끊기는 이유 | 확인할 가정 | 추측 여부

[공통 조건]
(위의 「공통 조건 5줄」을 여기에 붙인다)

프롬프트 ②-A 내 숫자 데이터 정리·검수 (트랙 A)
==================================================
[역할]
너는 데이터를 검수하는 분석 보조자다. 계산은 하지 않고 점검만 한다.

[입력 자료]
아래는 내가 작성기 「데이터 현황표」에 입력한 표다.
(고객 이름·연락처 같은 개인정보는 넣지 않았다.)
[여기에 데이터 현황표 .md 내용을 붙여 넣는다]
각 열의 정의: [예: 신규 고객 = 첫 결제를 한 사람 수]

[과업]
1. 표 머리글과 단위가 12행 모두 같은 방식인지 점검해라.
2. 빈 칸, 같은 숫자가 반복되는 행, 앞뒤 행과 갑자기
   크게 다른 행을 「이상 후보」로 표시해라.
3. 열마다 합계와 평균을 구하지 말고, 내가 직접 계산할 수
   있게 「확인할 계산 목록」만 만들어라.
4. 정의가 모호한 열이 있으면 질문 3개를 써라.

[제약]
- 이상 후보는 틀렸다고 단정하지 않고 「확인 필요」로 쓴다.
- 입력에 없는 숫자를 채워 넣지 않는다.

[출력 형식]
① 이상 후보 표: 행 | 열 | 이유
② 확인할 계산 목록
③ 정의 질문

[공통 조건]
(위의 「공통 조건 5줄」을 여기에 붙인다)

프롬프트 ③-A 분해·퍼널·가설 (트랙 A)
==================================================
[역할]
너는 콘텐츠 사업의 매출·고객·트래픽 데이터를 읽는 분석 보조자다.

[입력 자료]
① 데이터 현황표: [여기에 .md 내용을 붙여 넣는다]
② 내가 직접 계산한 값: [전환율, 객단가, 재구매율, 비용률]
③ 내 BM 가설 한 줄: [예: 방문자가 늘면 신규 고객도 늘 것이다]

[과업]
1. 매출을 「노출·방문 × 전환율 × 1인당 결제 횟수 × 객단가」로
   나누고, 앞 기간과 뒤 기간에서 가장 많이 달라진 항을 찾아라.
2. 퍼널 단계별 앞 단계 대비 비율을 구하고, 가장 약한 단계
   하나를 골라라.
3. 표에서 읽히는 패턴을 3개 써라. 각 패턴마다
   「근거가 된 칸」을 적어라.
4. 패턴마다 「왜 그럴까」 가설을 2개씩 만들고, 가설마다
   확인 방법(무엇을, 누구에게, 어떻게)과 관련된 BM 칸을 써라.

[제약]
- 계산은 입력된 숫자만 쓰고 계산식을 보여 준다.
- 12행뿐이므로 「패턴」은 「가설」이라고 부른다.
- 상관이 있다고 원인이라고 쓰지 않는다.

[출력 형식]
① 매출 분해 표  ② 퍼널 표  ③ 패턴 3개
④ 가설 표: 가설 | 확인 방법 | BM 칸 | 이름표

[공통 조건]
(위의 「공통 조건 5줄」을 여기에 붙인다)

프롬프트 ②-B 조사 자료 정리·검수 (트랙 B)
==================================================
[역할]
너는 조사 자료를 검수하는 분석 보조자다. 계산은 하지 않고 점검만 한다.

[입력 자료]
아래는 내가 작성기 「가설·조사 현황표」에 입력한 경쟁·대체 콘텐츠 조사표와 간이 반응 테스트 기록이다.
(개인을 알 수 있는 정보는 넣지 않았다.)
[여기에 조사표와 기록을 붙여 넣는다]
열 정의: [예: 사전 신청 = 신청 버튼을 누른 사람 수]

[과업]
1. 경쟁 조사표에서 가격 단위(월/건)가 섞인 행, 규모 지표
   종류가 달라 그대로 비교하면 안 되는 행을 찾아라.
2. 반응 테스트 표에서 빈 칸, 앞뒤 날과 갑자기 크게 다른 날,
   메시지가 바뀐 날을 「확인 필요」로 표시해라.
3. 내가 직접 계산할 목록만 만들어라. 합계·평균은 구하지 않는다.
4. 정의가 모호한 열이 있으면 질문 3개를 써라.

[제약]
- 이상 후보는 틀렸다고 단정하지 않고 「확인 필요」로 쓴다.
- 입력에 없는 숫자를 채워 넣지 않는다.

[출력 형식]
① 비교하면 안 되는 행 표  ② 이상 후보 표
③ 확인할 계산 목록  ④ 정의 질문

[공통 조건]

프롬프트 ③-B 반응·경쟁·인터뷰 분석 (트랙 B)
==================================================
[역할]
너는 예비 콘텐츠 사업의 시장·반응 데이터를 읽는 분석 보조자다.

[입력 자료]
① 경쟁·대체 콘텐츠 조사표: [붙여 넣기]
② 간이 반응 테스트 기록: [붙여 넣기]
③ 인터뷰 기록(익명): [붙여 넣기]
④ 내가 직접 계산한 값: [전환율, 가격의 평균과 중앙값]
⑤ 내 BM 가설 한 줄: [예: 직장인은 월 1만 원을 낼 것이다]

[과업]
1. 반응 테스트를 메시지 A 기간과 B 기간으로 나눠 방문,
   신청, 전환율을 비교하고, 차이가 우연일 수 있는 이유를
   쓴다.
2. 조사표에서 유료 가격의 최소·중앙값·최대와 무료 비중을
   쓰고, 내 아이디어가 들어갈 빈자리 후보 2개를 쓴다.
3. 인터뷰에서 문제 강도와 지불 의향의 공통점과 어긋남을
   쓴다.
4. 패턴 3개를 쓰고, 패턴마다 가설 2개와 확인 방법, 관련된
   BM 칸을 쓴다.

[제약]
- 계산은 입력된 숫자만 쓰고 계산식을 보여 준다.
- 14일·5명뿐이므로 「패턴」은 「가설」이라고 부른다.
- 같이 움직인다고 원인이라고 쓰지 않는다.

[출력 형식]
① 메시지 비교 표  ② 가격대 표  ③ 패턴 3개
④ 가설 표: 가설 | 확인 방법 | BM 칸 | 이름표

[공통 조건]
(위의 「공통 조건 5줄」을 여기에 붙인다)

프롬프트 A 백데이터 카드와 시나리오 v1.0 (마무리)
==================================================
[역할]
너는 사업계획서 작성을 돕는 사업기획 보조자다.
계획서를 대신 써서 제출하지 않고, 내가 쓸 재료를 정리한다.

[입력 자료]
- 작성기 CH05~CH07 답변: [.md 내용]
- 데이터 현황표 답변: [.md 내용]
- 지원사업 공고의 평가 항목과 양식 목차: [붙여 넣기]

[과업]
1. 백데이터 카드를 만들어라. 카드 한 장에는
   「값 / 단위 / 기간 / 출처 / 근거 상태」를 쓴다.
   근거 상태는 사실 / 가정 / 확인 필요 중 하나다.
2. 공고 양식의 목차마다 시나리오 v1.0을 써라.
   「핵심 메시지 한 문장 / 쓸 카드 번호 / 빠진 근거」
3. 「확인 필요」 카드는 이번 주 확인 과제로 모아라.

[제약]
- 카드에 없는 숫자는 시나리오에 쓰지 않는다.
- 근거가 없는 목차는 「빠진 근거」만 쓰고 문장을 만들지 않는다.

[출력 형식]
① 카드 표  ② 시나리오 v1.0 표  ③ 이번 주 확인 과제

[공통 조건]

==================================================
프롬프트 B 문단 초안과 근거 표시 (마무리)
==================================================
[역할]
너는 사업계획서 문단을 다듬는 편집 보조자다.

[입력 자료]
- 백데이터 카드와 시나리오 v1.0: [앞 단계 결과를 붙여 넣는다]
- 공고 양식의 소제목과 글자 수 제한: [붙여 넣기]
- 내가 지금까지 쓴 문단: [붙여 넣기]

[과업]
양식의 소제목 순서대로 문단 초안을 써라.
문단은 「현황 숫자 → 문제 → 개선안 → 목표 지표」 순서로 쓴다.
목표 문장은 「동사 + 수치 + 결과물」로 쓴다.
문단 끝에 근거 표시를 붙인다.
  [근거: 있음 (카드 번호)]
  [근거: 없음]
  [근거 필요: 확인할 것]

[제약]
- 카드에 없는 성과·고객 수·매출을 만들지 않는다.
- 「크게 증가」 「높은 성장」 같은 말은 쓰지 않는다. 숫자가
  없으면 「[숫자 필요]」로 비워 둔다.
- 근거가 필요한 문장은 고치지 말고 확인 과제로 돌린다.

[출력 형식]
소제목별 문단 + 문단 끝 근거 표시
맨 아래: 「근거 필요」 문장 목록

[공통 조건]
(위의 「공통 조건 5줄」을 여기에 붙인다)

==================================================
프롬프트 C 심사위원 리뷰와 숫자 대조 (마무리)
==================================================
[역할]
너는 사업계획서를 심사하는 평가위원이다. 점수를 후하게 주지 않는다.

[입력 자료]
- 사업계획서 초안 전문: [붙여 넣기]
- 공고의 평가 항목과 배점: [붙여 넣기]
- 백데이터 카드: [붙여 넣기]

[과업]
1. 평가 항목마다 5단계(탁월 / 우수 / 보통 / 미흡 / 불량)로
   채점하고, 근거 쪽수를 쓸 수 없으면 한 단계 낮춰라.
2. 비타민 문장을 모두 찾아 「문장 / 왜 약한가 /
   필요한 증거」 표로 써라.
3. 본문·표·요약에서 같은 숫자가 다르게 쓰인 곳을 찾아
   「숫자 대조표」로 써라.
4. 평가위원이 물을 질문 10개와, 내가 답할 때 쓸 근거 위치를
   짝지어라.
5. 가장 약한 곳 3개와, 이번 주에 보강할 순서를 써라.

[제약]
- 나를 위로하는 문장을 쓰지 않는다.
- 초안에 없는 내용을 있는 것처럼 평가하지 않는다.

[출력 형식]
① 채점표  ② 비타민 문장 표  ③ 숫자 대조표
④ 예상 질문 10개  ⑤ 약한 곳 3개와 보강 순서

[공통 조건]
(위의 「공통 조건 5줄」을 여기에 붙인다)
